In a traditional core Spring application (without Spring Boot), you use @ComponentScan when you want Spring to automatically detect and register your beans rather than forcing you to declare every single bean manually via Java @Bean methods or XML <bean> tags.

In Spring Boot, this annotation is implicitly hidden inside @SpringBootApplication. In vanilla Spring, you must explicitly configure it yourself.

When to Use It 

To Eliminate Boilerplate: When you have dozens of services, repositories, and controllers, manually writing @Bean methods for each one becomes tedious.

To Enable Stereotype Annotations: When you want Spring to look for classes marked with @Component, @Service, @Repository, and @Controller and automatically bring them into the application context.Complete Example (Vanilla Spring)Imagine a basic application with a service class (UserService) and a configuration class to wire everything up.

1. The Component (The class we want Spring to manage)We mark our class with @Component (or @Service) so Spring knows it should be managed.

package com.example.service;

import org.springframework.stereotype.Service;

@Service
public class UserService {
    public void createUser(String name) {
        System.out.println("User " + name + " created successfully!");
    }
}

2. The Configuration (Where @ComponentScan lives)Without Spring Boot, you create a configuration class. Here, you use @ComponentScan to point Spring toward the packages it needs to look through.  Java

package com.example.config;

import org.springframework.context.annotation.ComponentScan;
import org.springframework.context.annotation.Configuration;

@Configuration
// Tells Spring to search the 'com.example.service' package for components
@ComponentScan(basePackages = "com.example.service")
public class AppConfig {
    // No need to write manual @Bean methods for UserService anymore!
}

Tip: You can also pass multiple packages like @ComponentScan(basePackages = {"com.example.service", "com.example.dao"}) or use type-safe references like @ComponentScan(basePackageClasses = UserService.class).

3. Bootstrap the Application (No SpringApplication.run)Since we don't have Spring Boot's magic starter class, we must manually spin up the container using AnnotationConfigApplicationContext inside a classic main method.Javapackage com.example;

import com.example.config.AppConfig;
import com.example.service.UserService;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;

public class MainApplication {
    public static void main(String[] args) {
        // Initialize the Spring IoC Container using our configuration class
        AnnotationConfigApplicationContext context = 
                new AnnotationConfigApplicationContext(AppConfig.class);

        // Retrieve the automatically scanned bean from the context
        UserService userService = context.getBean(UserService.class);
        
        // Use it
        userService.createUser("John Doe");

        // Close the context safely
        context.close();
    }
}
The XML Alternative (For older Spring apps)If you are working on a legacy Spring project that uses XML instead of Java-based configurations, the exact equivalent of @ComponentScan is the <context:component-scan> tag:XML<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xmlns:context="http://www.springframework.org/schema/context"
       xsi:schemaLocation="http://www.springframework.org/schema/beans 
           http://www.springframework.org/schema/beans/spring-beans.xsd
           http://www.springframework.org/schema/context 
           http://www.springframework.org/schema/context/spring-context.xsd">

    <context:component-scan base-package="com.example.service" />

</beans>
To run this version, you would bootstrap your application using ClassPathXmlApplicationContext("beans.xml") instead.For a deeper dive into how this looks inside a project setup, this tutorial on Mastering Spring @ComponentScan Annotation provides a comprehensive walkthrough of configuring the annotation and handling common package scanning scenarios.

==========================
In a standard Spring application (without Spring Boot), a class annotated with @Configuration does not automatically scan for other components, even if they are in the same package. You must explicitly use @ComponentScan to trigger the search for beans annotated with @Component, @Service, @Repository, or @Controller. [1, 2, 3, 4, 5]
Here is why this requirement exists:
1. Separation of Responsibilities
•	@Configuration: Declares that a class contains specific bean definitions (methods marked with @Bean).
•	@ComponentScan: Acts as a "trigger" that tells Spring where to look for classes it should manage automatically.
Without this explicit trigger, Spring only processes the beans you have manually defined in your configuration class. [1, 2, 3, 4, 5]
2. Performance and Control
•	Selective Scanning: Automatically scanning every package could significantly slow down application startup and lead to accidental bean creation from external libraries.
•	Explicit Intent: By requiring @ComponentScan, Spring ensures you have made a conscious choice to use auto-detection rather than manual bean registration. [1, 2, 4, 5]
3. Default Scanning Behavior
When you add @ComponentScan without any arguments, it defaults to scanning the current package and all its sub-packages. This is why it seems redundant when your files are in the same package—the annotation is still needed to "turn on" the scanning feature itself. [, 2, 3, 4]
Note for Spring Boot Users
If you are using Spring Boot, you often don't need to add @ComponentScan manually. The @SpringBootApplication annotation already includes @ComponentScan by default, automatically covering everything in its own package and below. [1, 2, 3]
