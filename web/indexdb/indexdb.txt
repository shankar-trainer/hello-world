IndexedDB is a powerful low-level API for client-side storage of significant amounts of structured data, including files and blobs. Introduced as part of the HTML5 suite of technologies, it serves as a robust alternative to simpler storage methods like localStorage. 
Core Characteristics 

• NoSQL Database: IndexedDB is a transactional, object-oriented database system that stores data as key-value pairs rather than in tables with fixed columns. 
• Asynchronous Operations: All API calls are non-blocking, ensuring that database operations do not freeze the browser's UI thread. 
• Transactional Model: Every interaction (read or write) must occur within a transaction, ensuring data integrity. 
• Large Capacity: Unlike the 5-10MB limit of web storage, IndexedDB can typically store significantly larger amounts of data, often up to a percentage of the user's available disk space. 

Key Concepts & Components 

• Object Stores: These are analogous to tables in relational databases and hold the actual data objects. 
• Indexes: Special object stores used to look up records in a referenced object store based on specific properties, allowing for high-performance searches. 
• Cursors: Iterators used to traverse multiple records within an object store or index. 
• Versioning: Each database has a version number; schema changes (like creating or deleting object stores) can only be performed during a "version change" transaction.
