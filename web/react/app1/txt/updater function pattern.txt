The updater function pattern is a specific way of updating state in React by passing a function to the setter (e.g., setCount) instead of a direct value.

While it looks like a small syntax change, it’s a critical tool for ensuring your state updates are predictable, especially when dealing with rapid changes or asynchronous logic.

=============================================================

In React, the updater function pattern is the practice of passing a function to a state setter (like setCount) instead of a direct value. This is the "gold standard" for updating state when the new value depends on the previous one.

Why use it?
React batches state updates for performance. If you call a setter multiple times in a single scope using the direct value, they will conflict because they all reference the same "stale" snapshot of state from the current render.

An updater function guarantees you are working with the most recent state, even if other updates are pending.

The Pattern in Action
1. The "Standard" Way (The Risk)
If you try to increment three times like this, the result will only be 1 because count stays the same throughout this specific function execution.

JavaScript

const increment = () => {
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1); 
  // Result: count + 1
};
2. The Updater Pattern (The Fix)
By passing a function, React queues these updates and passes the intermediate result to the next function in line.

JavaScript

const increment = () => {
  setCount(prevCount => prevCount + 1);
  setCount(prevCount => prevCount + 1);
  setCount(prevCount => prevCount + 1);
  // Result: count + 3
};
Real-World Examples
Updating an Object
When updating a specific field in an object, the updater pattern ensures you don't accidentally wipe out other fields if multiple updates happen quickly (like a fast typist in a form).

JavaScript

const [user, setUser] = useState({ name: "Alex", score: 0 });

const updateScore = () => {
  setUser(prevUser => ({
    ...prevUser,
    score: prevUser.score + 1
  }));
};
Toggling a Boolean
This is the safest way to handle toggles to avoid "race conditions" where a user clicks faster than the component re-renders.

JavaScript

const toggle = () => {
  setIsOpen(prev => !prev);
};
Key Takeaways
Syntax: setState(prevState => nextState)

Reliability: Always use this when the next state is calculated using the previous state.

Identity: It helps avoid including state variables in the dependency arrays of useEffect or useCallback because you no longer need to reference the variable itself—only the updater.
