The useContext hook in React allows functional components to read and subscribe to context values, which is a mechanism for sharing data like themes or authentication status across the component tree without manually passing props at every level (known as "prop drilling"). 

How to Use useContext
Using useContext involves three main steps:
Create a Context
First, you create a context object using the createContext function. This object comes with a Provider and an optional default value.
jsx
// ThemeContext.js
import { createContext } from 'react';

export const ThemeContext = createContext('light'); // 'light' is the default value
Provide the Context
Wrap the components that need access to the context with the Context.Provider. Use the value prop to pass the data you want to share.
jsx
// App.js
import React, { useState } from 'react';
import { ThemeContext } from './ThemeContext';
import ThemedComponent from './ThemedComponent';

function App() {
  const [theme, setTheme] = useState('light');

  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <h1>Context Example</h1>
      <ThemedComponent />
    </ThemeContext.Provider>
  );
}
Consume the Context
In any functional descendant component, use the useContext hook with the context object you created to access the current value.
jsx
// ThemedComponent.js
import React, { useContext } from 'react';
import { ThemeContext } from './ThemeContext';

function ThemedComponent() {
  // Access the value provided by the nearest ThemeContext.Provider above it
  const { theme, setTheme } = useContext(ThemeContext);

  const toggleTheme = () => {
    setTheme(prevTheme => (prevTheme === 'light' ? 'dark' : 'light'));
  };

  return (
    <div style={{ background: theme === 'dark' ? 'black' : 'white', color: theme === 'dark' ? 'white' : 'black' }}>
      <p>Current theme: {theme}</p>
      <button onClick={toggleTheme}>Toggle Theme</button>
    </div>
  );
}


When to Use useContext
Global State Management: Ideal for data needed across many components, such as user authentication, themes, or language preferences.
Avoiding Prop Drilling: When you want to pass data to deeply nested components without passing it through intermediate components that don't need it.
Simple State Sharing: A great, built-in alternative to third-party state management libraries (like Redux) for smaller applications with simpler state requirements. 


Caveat: When the context value changes, all components that consume that context will automatically re-render. For performance-critical applications with frequent updates, optimization techniques like useMemo and useCallback might be necessary, or a dedicated state management library might be a better fit.

1. Create the Context (EmployeeContext.js)
First, we need a central "brain" to hold the employee state and the functions to manipulate it.

import React, { createContext, useState } from 'react';

export const EmployeeContext = createContext();

export const EmployeeProvider = ({ children }) => {
  const [employees, setEmployees] = useState([]);

  const addEmployee = (newEmployee) => {
    setEmployees([...employees, { ...newEmployee, id: Date.now() }]);
  };

  return (
    <EmployeeContext.Provider value={{ employees, addEmployee }}>
      {children}
    </EmployeeContext.Provider>
  );
};

import React from 'react';

Contexts in React.js
In React, context contextrefers to a feature that allows data to be passed through the component hierarchy without having to explicitly pass props manually at each level.

With context, we can share data between components without having to perform prop drilling(pass data through multiple levels of components) and makes it easier to manage the overall state of the application.


The React.js context consists of two main parts:

  Provider : A component that wraps a set of child components and provides them with access to shared data. The provider has a property called value, which contains the data that you want to share with the child components.
  Consumer : A component used to access data provided by the Provider. Consumer components must be nested within the Provider in the component hierarchy.

To work with the context in React, the most commonly used way currently is through Hooks, specifically the Hook useContext, which will help consumer components access the context value provided by the closest Provider component in the component hierarchy.


Hook useContext
useContextis a HookReact component that allows functional components to access the value of a context provided by the closest Provider component in the component hierarchy.

useContexttakes as argument the context object created with React.createContextand returns the current value of the context.

The basic syntax and steps to use it Hook useContextare as follows:

1- Create our context.
import React from 'react';

export const myContext = React.createContext('Default value');
The initial value for the context myContextis 'Default value'. If any Consumer component attempts to consume this context, but does not find a corresponding Provider in its hierarchy, this value will be used 'Default value'as the context value.

2- Create our supplier
import React from "react";
import { myContext } from "./context";

export function ProviderContextComponent() {
  const sharedData = "My shared data!";

  return (
    <myContext.Provider value={sharedData}>

      {/* children components */}

    </myContext.Provider>
  );
}
The component ProviderContextComponentacts as the provider and wraps the child components with the context provided by Context.Provider , in turn, we are overwriting the initial default value. Finally we must add {/* children components }the consumer components in the section to obtain the shared value.

3- Create our consumer
import React, { useContext } from 'react';
import { myContext } from './context';

export function ConsumerContextComponent() {
  const data = useContext(myContext);

  return (
    <div>Data shared is: {data}</div>
  );
};
The component ConsumerContextComponentuses useContextto directly access the value of the context provided by the Provider ( sharedData) and displays it in the user interface.

Key Features of Contexts in React.js
Context in React useContextis a powerful and flexible feature that offers several important advantages for handling global state and communicating between components. Below are some of the key features of context in React useContext:

Sharing data globally : Context allows data to be shared globally between components without the need to explicitly pass props across multiple component levels. This avoids the hassle prop drillingand makes it easier to manage global state in the application.
Ease of consumption : With useContext, consuming data from the context is much simpler and cleaner compared to using Consumer. Consumption is done directly in the functional component using a more concise syntax.
Reactivity : When the context value changes, all Consumer components that are subscribed to that context will automatically re-render with the new updated value.
Provider Nesting : You can have multiple Providers nested in the component hierarchy, allowing you to set different values ​​for specific contexts in different parts of the application.
Performance improvement : The context uses a shallow comparison to detect if the context value has changed, which can lead to improved performance by not unnecessarily rendering consumer components when the value does not change.
Code Cleanliness : By using context with useContext, you can keep your code cleaner and more readable by avoiding passing unnecessary props across multiple components.
Replacing Redux in simple cases : In smaller applications or with simpler global state, context useContextcan replace the use of libraries like Redux for handling global state, reducing configuration overhead and simplifying the project structure.
Easy migration from previous versions : If you are using the older context API based on contextTypesand childContextTypes, migrating to useContextis relatively easy and will allow you to take advantage of the more modern, readable syntax.
Considerations when using the useContext Hook
When using the Hook useContextin React, it is important to keep in mind a few considerations to ensure you use it correctly and avoid potential issues:

Avoid too many contexts : While context is a powerful tool, it is not suitable for every situation. Avoid creating too many contexts, as this can unnecessarily complicate your application structure and make it difficult to follow the flow of data. Consider other options such as props or local state where more appropriate.
Performance : While the context useContextprovides a convenient way to share data globally, keep in mind that changes to the context may cause all consumer components to re-render. If you have many consumer components, this can impact performance. Whenever possible, try to limit the number of consumer components subscribed to the context.
Context too large : If the context value is a large object or changes very frequently, it can have a negative impact on the performance and responsiveness of the application. In these cases, consider splitting the context into multiple smaller, more specific contexts to avoid unnecessary renderings.
Avoid using context for non-shared data : Context is great for sharing global data or data that is shared widely between components, but it is not suitable for data that is specific to a component or only used in a specific place. For data that is local to a component, it is better to use local state or props.
Testability : When using context, make sure your components are easily testable. Note that consumer components are context dependent, so when writing tests, it may be necessary to provide a mock or fake context to avoid depending on the real context during unit testing.
useContext vs useReducer
Both useContextcan useReducerbe used to manage global states in a React application, but they have different approaches and use cases. Here are the key differences:

useContext:

Used to access global data shared across the entire application.
Allows you to avoid manually passing props across multiple components.
Provides a mechanism for sharing data within a context and accessing it from any component in the tree.
Best suited for simple global state or data that needs to be available across many components.
Ideal for components that only need to consume global data, but not perform complex updates to it.
useReducer:

Used to handle more complex global states and advanced update logic.
It is based on a reducer function that specifies how to update the state based on the provided actions.
It is most suitable when the global state has multiple sub-values ​​or when more advanced update logic is required.
Provides a more organized and scalable structure for handling complex states.
Ideal for components that need to make changes to global state through specific actions and more sophisticated updates.
In short, useContextit's useful for sharing simple global data and accessing it across the entire application, while useReducerit's better suited for handling more complex global states with advanced update logic. You can use them together in situations where you need both global data access and more sophisticated updates.
