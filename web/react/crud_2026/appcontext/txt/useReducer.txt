The useReducer hook in React is a powerful alternative to useState for managing complex state logic. 
It uses a reducer function to handle state transitions based on dispatched actions.

Example: Counter with Increment and Decrement

import React, { useReducer } from 'react';

// Reducer function to handle state transitions
const counterReducer = (state, action) => {
    switch (action.type) {
        case 'INCREMENT':
        return { count: state.count + 1 };
        case 'DECREMENT':
        return { count: state.count - 1 };
        default:
        return state;
    }
};

function Counter() {
const [state, dispatch] = useReducer(counterReducer, { count: 0 });

return (
<div>
<p>Count: {state.count}</p>
<button onClick={() => dispatch({ type: 'INCREMENT' })}>Increment</button>
<button onClick={() => dispatch({ type: 'DECREMENT' })}>Decrement</button>
</div>
);
}

export default Counter;

Key Points

  Reducer Function: The counterReducer function defines how the state changes based on the action type (INCREMENT or DECREMENT).

  Dispatch: The dispatch function triggers the reducer with an action object, updating the state accordingly.

  Initial State: The initial state is passed as the second argument to useReducer.

Considerations

  Always return a new state object in the reducer to avoid mutating the existing state.

  Use useReducer when managing complex state logic or when multiple related state variables need to be updated together. 
  For simpler cases, useState might be more appropriate.

useReducer is a React Hook designed for managing complex state logic. While useState is great for simple values 
(like a toggle or a counter), useReducer is better when your state has multiple sub-values or when the next state depends on 
the previous one.

It is heavily inspired by Redux and follows a "dispatch an action" pattern.

The Four Core Parts
To use useReducer, you need to understand these four elements:

State: The current data/snapshot of your component.

Action: An object that describes what happened (e.g., { type: 'increment' }).

Reducer: A function that takes the state and action, then returns the new state.

Dispatch: A function you call to "send" an action to the reducer.

Basic Implementation
Here is the standard structure of a reducer setup:

JavaScript
// 1. Define the initial state
const initialState = { count: 0 };

// 2. Define the reducer function
function reducer(state, action) {
  switch (action.type) {
    case 'increment':
      return { count: state.count + 1 };
    case 'decrement':
      return { count: state.count - 1 };
    default:
      return state;
  }
}

// 3. Use it in your component
const [state, dispatch] = useReducer(reducer, initialState);
Why use useReducer over useState?
Feature	useState	useReducer
Logic Location	Inside the component.	Outside the component (cleaner).
State Transitions	Simple updates.	Complex, predictable transitions.
Testing	Harder to test state logic alone.	Easy to test the reducer function.
Dependencies	Hard to manage multiple values.	Excellent for related state (e.g., a form).
Real-World Example: A Complex Form
If you are managing a book entry form with fields for title, author, and isAvailable, useReducer keeps all that logic in one place rather than having three separate useState calls.

JavaScript
const formReducer = (state, action) => {
  return {
    ...state,
    [action.field]: action.value
  };
};

// Usage inside component
const [formState, dispatch] = useReducer(formReducer, { title: '', author: '' });

const handleChange = (e) => {
  dispatch({ 
    field: e.target.name, 
    value: e.target.value 
  });
};

useState and useReducer are React hooks for state management. useState is best for simple, independent state (booleans, strings, numbers), while useReducer is superior for complex state objects, interrelated data, or when the next state depends on the previous one. useReducer centralizes update logic, improving maintainability in complex scenarios. 

Key Differences:
Complexity & Structure: useState updates state directly with a setter function, ideal for single values. useReducer uses a reducer function and actions (dispatch) to update state, managing multiple related values.
Logic Location: useState keeps update logic inside the component handler. useReducer moves logic outside the component into a reducer function, making it easier to test and reuse.
Predictability: useReducer is often better for complex state transitions, as it enforces that state changes only occur through specific, named actions.
Setup Time: useState is faster to set up (simple API). useReducer requires more boilerplate (reducer, actions, initial state). 


When to Use Which:
useState: Simple state, toggle switches, form inputs, or when state variables don't depend on each other.
useReducer: Complex object state, interrelated data, state that depends on previous values, or when multiple actions 
need to update the same state. 


useReducer can also offer performance benefits when passing callbacks down to heavily optimized components, as the dispatch function identity is stable and does not change 
between re-renders

Combining useContext and useReducer is a powerful pattern in React. 
It essentially creates a "mini-Redux" state management system without needing any external libraries.

While useReducer handles the logic of how state changes, useContext handles the distribution of that state (and the dispatch function) to any component in your app.

The Architecture
The Reducer: Defines the state and the rules for updating it.

The Context: Creates the "tunnel" to pass the state down.

The Provider Component: A wrapper that holds the useReducer hook and passes the state and dispatch into the Context.

Implementation Example
Let's build a simple system to manage a list of items (like a book collection or a task list).

1. Create the Reducer and Context
JavaScript
import React, { createContext, useReducer } from 'react';

// Initial state
const initialState = { items: [] };

// Reducer function
const listReducer = (state, action) => {
  switch (action.type) {
    case 'ADD_ITEM':
      return { ...state, items: [...state.items, action.payload] };
    case 'REMOVE_ITEM':
      return { ...state, items: state.items.filter(item => item.id !== action.payload) };
    default:
      return state;
  }
};

// Create Context
export const ListContext = createContext();
2. Create the Provider
This component wraps your app (or a section of it) to provide the state globally.

JavaScript
export const ListProvider = ({ children }) => {
  const [state, dispatch] = useReducer(listReducer, initialState);

  return (
    <ListContext.Provider value={{ state, dispatch }}>
      {children}
    </ListContext.Provider>
  );
};
3. Consume the State and Dispatch
Now, any child component can both read the list and update it.

JavaScript
import React, { useContext } from 'react';
import { ListContext } from './ListProvider';

const AddItemButton = () => {
  const { dispatch } = useContext(ListContext);

  const handleAdd = () => {
    dispatch({ type: 'ADD_ITEM', payload: { id: 1, name: 'New Entry' } });
  };

  return <button onClick={handleAdd}>Add Item</button>;
};
Why this pattern is better than useState + useContext
Avoids Prop Drilling: You don't have to pass functions down through five layers of components.

Predictable Updates: All state transitions are centralized in the reducer, making it easier to debug.

Performance: You can pass the dispatch function down separately. Since dispatch never changes identity, components that only need to trigger actions won't re-render when the state changes.

Scalability: As your state grows (e.g., adding search filters, loading statuses, or categories), you just add more cases to your reducer instead of creating ten different useState hooks.

Performance Tip
If your app gets very large, wrap your context value in useMemo to prevent unnecessary re-renders of all consumers every time the parent component renders.
