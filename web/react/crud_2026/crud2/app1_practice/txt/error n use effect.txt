The reason you are seeing this error is because of how you've defined the submit variable. You have accidentally wrapped your function in an array-like structure (likely intending to use useCallback but forgetting to actually call the hook).

Specifically, this part of your code is creating an array (which is an object type in JavaScript) rather than a function:

JavaScript

// This is being evaluated as an array: [function, [id]]
const submit = ((e) => { 
  /* ... */ 
}, [id])


Option 1: The Simple Fix (Recommended)
Since this is a search form, you don't strictly need a hook here. Just define it as a standard arrow function.

JavaScript

const submit = (e) => {
  e.preventDefault();
  axios.get('http://localhost:2000/employee/' + id)
    .then(response => {
      const data = response.data;
      setName(data.name);
      setSalary(data.salary);
      setMessage("record found " + JSON.stringify(data));
      setLoading(false);
    })
    .catch(e => {
      setError(e.message);
      setLoading(false);
    });
}; // Removed the trailing comma and [id]
Option 2: Using useCallback
If you intended to memoize the function (which is what that [id] syntax suggests), you must explicitly use the useCallback hook from React.

JavaScript

import { useState, useCallback } from 'react'; // Make sure to import it

const submit = useCallback((e) => {
  e.preventDefault();
  // ... your axios logic ...
}, [id]); // Now the dependency array is valid because it's part of the hook
Why the error happened
In JavaScript, if you write const x = (function, [dep]), the comma operator evaluates both but returns the last one, or in your specific syntax, it looks like you were trying to pass arguments to a hook that wasn't there.

The useEffect hook is the "Swiss Army knife" of functional components, but its behavior changes drastically depending on that second argument: the dependency array.

Think of it as telling React when to look at your code and decide whether to run it again.

1. No Dependency Array
useEffect(() => { ... })

If you omit the array entirely, the effect runs after every single render.

When it runs: On the initial mount and every time the component updates (state changes, prop changes, or parent re-renders).

The Risk: This is rarely what you want. If you update state inside this effect without a guardrail, you will trigger a re-render, which triggers the effect, which triggers a re-render... creating an infinite loop.

Use Case: Very niche logging or global manual DOM updates that must sync with every change.

2. Empty Dependency Array
useEffect(() => { ... }, [])

Adding an empty array tells React, "This effect doesn't depend on any values from props or state, so it never needs to re-sync."

When it runs: Only once, immediately after the component mounts (the first render).

The Benefit: It’s perfect for one-time setups.

Use Case: Fetching initial data from an API, starting a timer, or subscribing to a WebSocket.

3. With Dependencies
useEffect(() => { ... }, [data])

This is the most common and precise way to use the hook.

When it runs: On mount, and then only if the value of data has changed since the last render.

How it compares: React performs a "shallow comparison" (using Object.is) on every item in the array. If even one value is different, the effect fires.

Use Case: Re-fetching user details when a userId prop changes, or updating a document title based on a count state.

Summary Table

Syntax	Run frequency	Typical Use Case
useEffect(fn)	Every render	General synchronization (rare).
useEffect(fn, [])	Once (Mount only)	API calls, event listeners.
useEffect(fn, [dep])	On change of dep	Syncing state to external APIs/logs.
Pro-Tip: If you use a variable inside your effect (like a prop or state), React's ESLint rules will insist you include it in the dependency array. Ignoring this can lead to "stale closures," where your effect is looking at old data from a previous render.

useEffect with depedency and without dependency


The primary difference is the triggering condition for the side effect: useEffect without a dependency array runs after every component render, while useEffect with an empty dependency array ([]) runs only once, after the initial render (mount). 

useEffect without a Dependency Array (Omitted) 
When you omit the second argument, the effect runs after every single render of the component. 

Behavior: The code inside the effect function executes after the initial render and every subsequent update (e.g., state or prop changes).
Use Cases: This is rarely needed and can easily lead to performance issues or infinite loops if not carefully managed (e.g., if it updates a state that causes a re-render). It can be used for logging or specific scenarios where an action is truly needed after every DOM update.

Example:
javascript
useEffect(() => {
  // This code runs after every render
  console.log("Effect ran after every render");
}); 
 

useEffect with an Empty Dependency Array ([]) 

When you provide an empty array as the second argument, you tell React that the effect does not depend on any reactive values from the component's scope. 
Behavior: The effect runs only once after the initial render of the component. This behavior mimics the componentDidMount lifecycle method in class components.
Use Cases: It is ideal for one-time setup logic:
Fetching initial data from an API.
Setting up subscriptions or event listeners (with a proper cleanup function returned by the effect).
Initializing a third-party library.
Example:
javascript
useEffect(() => {
  // This code runs only once, on mount
  fetchInitialData();
  return () => {
    // Cleanup logic runs on unmount
  };
}, []);
 

useEffect with Dependencies ([value1, value2]) 
This is the most common and recommended usage, where you include all the reactive values (props, state, functions defined within the component) that the effect uses. 

Behavior: The effect runs after the initial render and then only again if any of the values in the dependency array have changed since the previous render.

Use Cases:
Fetching data when a specific parameter (like a user ID) changes.
Updating the document title based on a state change.
Example:
javascript
useEffect(() => {
  // This code runs on mount and whenever 'count' changes
  document.title = `Count: ${count}`;
}, [count]);
