Actuator

•Is a module that provides production-ready features for 
monitoring and managing a running Spring Boot application using 
HTTP endpoints or JMX. 
•It exposes built-in endpoints that offer insights into the 
application's internals, such as health status, metrics, and 
environment properties, with minimal configuration required.



Key Features

•Monitoring: Provides real-time visibility into the application's 
performance and resource usage, essential for production 
environments.
•Management: Allows developers and operations teams to interact with 
the application, modify logging levels, view configurations, and perform 
controlled shutdowns.
•Metrics Integration: Uses Micrometer, an application metrics facade, to 
provide dimensional metrics that can be scraped by systems like 
Prometheus, Datadog, and New Relic.
•Customization: Supports the creation of custom endpoints to expose 
application-specific data or operations tailored to unique 
requirements. 



Commonly Used Endpoints

•Actuator endpoints are available under the default path /actuator. 




•Once the application is running (e.g., on http://localhost:8080), 
one access various monitoring data via the /actuator base path.

Configuration and Security

•By default, in Spring Boot 3.x, only the health endpoint is exposed over 
HTTP for security reasons. 
•Exposing Endpoints: To expose more endpoints, use the 
management.endpoints.web.exposure.includeproperty in your 
application.propertiesfile. For example, 
management.endpoints.web.exposure.include=health,info,metrics.
•Security Best Practices: Due to the potential for exposing sensitive data 
(e.g., environment variables, credentials) or enabling RCE if 
misconfigured, it is critical to secure Actuator endpoints using proper 
authentication and authorization (e.g., with Spring Security) or by 
placing them behind a firewall. 



Accessing Metric Details

•For metrics, the base URL lists available metrics (e.g., 
system.cpu.count) can then access specific metric details by 
appending the metric name to the URL: 


http://localhost:8080/actuator/metrics/system.cpu.count 


Custom Health Indicator

create custom health indicators by implementing the HealthIndicator interface to check the status of specific parts of your application. 

import org.springframework.boot.actuate.health.Health;

import org.springframework.boot.actuate.health.HealthIndicator;

import org.springframework.stereotype.Component;

@Component

public class CustomHealthIndicatorimplements HealthIndicator {

@Override

public Health health() {

// Perform a custom check, e.g., connectivity to a specific external service

if (isServiceUp()) {

return Health.up().withDetail("customServiceStatus", "Operational").build();

} else {

return Health.down().withDetail("customServiceStatus", "Offline").build();

}

}

private booleanisServiceUp() {

// Logic to check the service status (e.g., ping a URL, check a database connection)

return true; // return true if the service is up

}

}

resilience4j-circuitbreaker configurations.

•Resilience4jis a lightweight, fault-tolerance library designed 
specifically for Java applications. 
•It provides various resilience patterns, including circuit breakers, 
rate limiters, retries, timeouts, and bulkheads. 
•Resilience4j was created as a more modular, flexible alternative to 
Netflix’s Hystrix, allowing developers to select and configure only 
the resilience mechanisms they need.
•



•sliding-window-type: The number of requests is recorded and 
aggregated in the last “sliding-window-size” seconds.
•failure-rate-threshold: Trigger Circuit Breaker if at least “failure-
rate-threshold” of requests have failed.
•minimum-number-of-calls: Records at least “minimum-number-
of-calls” requests in the last “sliding-window-size” seconds before 
calculating the failure rate.
•



•automatic-transition-from-open-to-half-open-enabled: After ”wait-
duration-in-open-state” seconds, Circuit Breaker will automatically 
transition from open to half-open state.
•wait-duration-in-open-state: If triggered, wait at least “wait-duration-
in-open-state” seconds before allowing more calls.
•permitted-number-of-calls-in-half-open-state: After “wait-duration-
in-open-state” time has passed, allow another “permitted-number-of-
calls-in-half-open-state” requests and wait for them to calculate the 
failure rate again.
•sliding-window-size: Record the result of the last “sliding-window-
size” seconds.
