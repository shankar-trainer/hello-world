Log4j


•Apache Log4jis a widely used, open-source Java-based logging 
utility maintained by the Apache Software Foundation. 
•It allows developers to record system events, errors, and 
diagnostic messages in Java applications
•Apache Log4j is a powerful, Java-based logging utility used to 
record application activity. 
•While Log4j 1 is end-of-life, the modern standard is Log4j 2, which 
offers improved performance and flexibility. 



Why Developers Use It

•Event Tracking: It traces the flow of applications, which is crucial 
for debugging and analyzingerrors.
•Flexibility: Developers can set logging levels (e.g., info, debug, 
error) and output the logs to various destinations like consoles, 
files, or databases.



Main components

•Log4j operates using three main components:
•Loggers: Captures logging information from the application code.
•Appenders: Delivers log events to destinations like the console, files, or 
databases.





•Layouts: Formats the log events in different styles (e.g., HTML, JSON, or 
custom patterns).





Standard Logging Levels

•Logging levels allow you to filter messages by severity. The levels, 
in descending order of severity, are
•FATAL: Severe errors that cause the application to crash.
•ERROR: Runtime errors or unexpected conditions.
•WARN: Use of deprecated APIs or "almost" errors.
•INFO: Interesting runtime events (e.g., application startup/shutdown).
•DEBUG: Detailed information for debugging.
•TRACE: Most fine-grained informational events.

Basic Setup (Log4j 2)

Add Dependencies: Include the Log4j 2 library in your project (e.g., via Maven or Gradle).
Create Configuration: Save a file named log4j2.xml in your src/main/resources folder.
<Configuration status="WARN">

<Appenders>

<Console name="Console" target="SYSTEM_OUT">

<PatternLayoutpattern="%d{HH:mm:ss.SSS} [%t] %-5level %logger{36} -%msg%n"/>

</Console>

</Appenders>

<Loggers>

<Root level="debug">

<AppenderRefref="Console"/>

</Root>

</Loggers>

</Configuration>


Implement in Code

Obtain a logger instance and start logging.
import org.apache.logging.log4j.LogManager;

import org.apache.logging.log4j.Logger;

public class MyClass{

private static final Logger logger= LogManager.getLogger(MyClass.class);

public static void main(String[] args) {

logger.info("Hello, Log4j!");

logger.error("An error occurred.");

}

}


Advanced Features

•File Logging: Use a FileAppenderor RollingFileAppenderto save 
logs to local files.
•Dynamic Configuration: Log4j can automatically reload 
configuration files at runtime without restarting the application.
•Format Patterns: Use conversion characters like %d (date), %p 
(priority/level), and %m (message) to customize log appearance.



FileAppender

•FileAppenderis a component that directs log messages out of the console and writes them into a physical file on your disk.
FileAppenderConfiguration


log4j2.xml

<?xml version="1.0" encoding="UTF-8"?>

<Configuration status="WARN">

<Appenders>

<!--Define the File Appender-->

<File name="MyFileAppender" fileName="logs/app.log" append="true">

<PatternLayoutpattern="%d{yyyy-MM-dd HH:mm:ss.SSS} [%t] %-5level %logger{36} -%msg%n"/>

</File>

</Appenders>

<Loggers>

<!--Connect the Appenderto the Root Logger -->

<Root level="info">

<AppendersRefref="MyFileAppender"/>

</Root>

</Loggers>

</Configuration>


Key attributes

•name: A unique identifier for the appender(used when referencing it in the 
<Loggers> section).
•fileName: The path and name of the file where logs will be written. It can be 
relative (e.g., logs/app.log) or absolute (e.g., /var/log/myapp/app.log). Log4j 
will automatically create missing directories.
•append:
•true (Default): New logs are added to the end of the existing file.
•false: The file is truncated (cleared out) every time the application restarts.



•PatternLayout: Defines how the log message is formatted.
•%d: Timestamp
•%t: Thread name
•%-5level: Logging level (INFO, WARN, ERROR, etc.), aligned to 5 characters.
•%msg: The actual log message.
•%n: Platform-dependent line separator.






RollingFileAppender

•FileAppenderis great for small projects or testing, it has a major 
drawback: the log file will grow indefinitelyuntil your disk runs 
out of space.
•For production environments, it is highly recommended to use a 
RollingFileAppender. 
•This automatically "rolls" (backs up and clears) the log file based 
on size or time.



•Configure three main things:
•fileName: The path to the active log file currently being written to.
•filePattern: The naming archive pattern for files that have been rolled over.
•Policies & Strategies: When to roll the file (Triggering Policy) and how to 
manage the archived files (Rollover Strategy).






log4j2.xml

<RollingFilename="RollingFileAppender" 

fileName="logs/app.log" 

filePattern="logs/archive/app-%d{yyyy-MM-dd}-%i.log.gz">

<PatternLayoutpattern="%d %p %c{1.} [%t] %m%n"/>

<Policies>

<!--Roll over every day -->

<TimeBasedTriggeringPolicyinterval="1" modulate="true"/>

<!--OR roll over if the file reaches 10 Megabytes -->

<SizeBasedTriggeringPolicysize="10 MB"/>

</Policies>

<!--Keep a maximum of 10 archived files -->

<DefaultRolloverStrategymax="10"/>

</RollingFile>
