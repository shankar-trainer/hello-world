Spring bootconfigserver


Key features

•provides centralized configuration management for microservices in a 
distributed system.
•Centralized management:A single server manages configuration 
properties for all applications and environments (e.g., development, 
testing, production).
•Version control:By default, the config server uses a Git repository as 
its backend, which offers versioning, labeling, and auditing of 
configuration changes. Other backends like HashiCorpVault, JDBC, 
and the local file system are also supported.
•



•Dynamic updates: It supports refreshing configurations at runtime 
without needing to restart the microservices. This is enabled by 
the Spring Boot Actuator /actuator/refresh endpoint and the 
@RefreshScope annotation.
•Encrypted properties: The server can symmetrically or 
asymmetrically encrypt and decrypt property values to secure 
sensitive data.
•API-based access: Configuration data is exposed through an HTTP 
API, making it accessible to any application that can make an 
HTTP request, regardless of language.

Enable the config server

import org.springframework.boot.SpringApplication;

import org.springframework.boot.autoconfigure.SpringBootApplication;

import org.springframework.cloud.config.server.EnableConfigServer;

@EnableConfigServer

@SpringBootApplication

public class ConfigserverApplication {

 public static void main(String[] args) {

 SpringApplication.run(ConfigserverApplication.class, args);

 }

}


Configure the Git repository 

•In the src/main/resources/application.properties (or 
application.yml) file of the config server, specify the Git repository 
where the configuration files are stored. 
•The server typically runs on port 8888 by convention.
