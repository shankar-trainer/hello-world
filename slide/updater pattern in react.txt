updater pattern


•is a specific way of updating state in React by passing a function to the 
setter (e.g., setCount) instead of a direct value.
•is the practice of passing a function to a state setter (like setCount) 
instead of a direct value.
•This is the "gold standard" for updating state when the new value 
depends on the previous one.
•Why use it?
•Why use it?
•React batches state updates for performance. 
•If you call a setter multiple times in a single scope using the direct value, 
•they will conflict because they all reference the same "stale" snapshot of state 
from the current render.






•An updater function guarantees you are working with the most 
recent state, even if other updates are pending.
•looks like a small syntax change, it’s a critical tool for ensuring 
your state updates are predictable, especially when dealing with 
rapid changes or asynchronous logic.
•The Pattern Syntax
•Instead of passing the next state directly:setCount(count + 1)
•pass a callback function that receives the pending state as an 
argument:setCount(prevCount=> prevCount+ 1






•If you call a standard setter multiple times in a single event handler, 
they all reference the same "snapshot" of state from the start of the 
render.
•The Problem:


JavaScriptconsthandleClick= () => {

setCount(count + 1); // count is 0

setCount(count + 1); // count is still 0

setCount(count + 1); // count is still 0

// Result: count becomes 1, not 3.

};


The Solution (Updater Function)

•React queues these functions and runs them in order, passing the 
result of the previous update to the next one.


JavaScriptconsthandleClick= () => {

setCount(prev=> prev+ 1); // prev= 0, returns 1

setCount(prev=> prev+ 1); // prev= 1, returns 2

setCount(prev=> prev+ 1); // prev= 2, returns 3

// Result: count becomes 3.

};
