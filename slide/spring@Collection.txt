@ElementCollection


•The @ElementCollection annotation in JPA (Jakarta Persistence 
API) is used to map a collection of basic types (e.g., String, 
Integer) or embeddable classes (classes annotated with 
@Embeddable) that are not entities. 
•It provides a way to store dependent value types in a separate 
database table without needing to create a separate entity class 
for them. 



Key Characteristics

•No Independent Identity: The elements in an @ElementCollection 
do not have their own primary key and cannot exist independently 
of the parent entity.
•Private Ownership: The elements are "owned" by the containing 
entity. They are persisted, merged, and removed with the parent 
entity.
•Separate Table: The collection is stored in a separate table, which 
is defined using the @CollectionTable annotation.
•Lazy Loading: By default, element collections are lazily loaded 
(FetchType.LAZY). 



@Entity

public class Person {

@Id

private String ssn;

private String name;

@ElementCollection

@CollectionTable(name="PERSON_NICKNAMES", 
joinColumns=@JoinColumn(name="person_ssn"))

@Column(name="nickname")

private Set<String> nickNames= new HashSet<>();

}


@ElementCollection vs. @OneToMany

•@ElementCollection: Used for collections of basic types or 
@Embeddable objects (Value Types).
•@OneToMany: Used for collections of other @Entity classes 
(Entities) that have their own lifecycle. 
•Common Pitfalls
•Performance: When a collection is changed, Hibernate often deletes all 
existing entries and re-inserts them, which can be inefficient for large 
collections.
•Querying: It can be harder to query directly compared to entities, often 
requiring a JOIN.
•Nesting: You cannot nest @ElementCollection inside another 
@Embeddable object within an element collection. 






@Embeddedand @ElementCollection

•@Embedded maps a single value-type object into the same table as the 
parent entity, 
•@ElementCollection maps a collection of value-type objects (basic or 
embeddable) to a separate table. 
•@Embedded
•Purpose: Used to include the properties of a reusable, dependent class (annotated with 
@Embeddable) within the parent entity's table as a value type.
•Database Mapping: The fields of the embedded object become columns in the parent 
entity's table. No separate table is created for the embedded object itself.
•Lifecycle: The embedded object shares the parent entity's lifecycle and identity. It 
cannot be independently queried or managed by an EntityManager.
•Usage: Ideal for grouping related fields within a single entity, like an Address object 
(street, city, zip) that logically belongs to a User and is always accessed with that User. 






@Embeddable

public class Address {

 private String street;

 private String city;

}

@Entity

public class User {

 @Id

 private Long id;

 private String name;

 @Embedded // Maps street and city columns to the User table

 private Address address;

}


@ElementCollection

•Purpose: Used to map a collection (e.g., List, Set, Map) of basic 
types (like Strings or Integers) or embeddable objects.
•Database Mapping: A separate "collection table" is created to 
store the elements. This table has a foreign key column 
referencing the primary key of the parent entity's table.
•Lifecycle: The elements in the collection are still strictly owned by 
the parent entity and do not have their own persistent identity 
(@Id). Operations on the elements are cascaded from the parent.
•Usage: Suitable for storing multiple values that don't warrant their 
own full entity, such as a list of email addresses or phone 
numbers for a single user. 



@Entity

public class User {

 @Id

 private Long id;

 private String name;

 @ElementCollection // Creates a separate table (e.g., USER_EMAILS)

 @CollectionTable(name = "USER_EMAILS", joinColumns = 
@JoinColumn(name = "USER_ID"))

 @Column(name = "EMAIL_ADDRESS")

 private Set<String> emailAddresses;

}
