Git branch


•In Git,a branch is essentially a lightweight, movable pointer to a 
specific commit, allowing to isolate development work without 
affecting the main codebase.
•In Git, a branch is like a separate workspace where you can make 
changes and try new ideas without affecting the main project. 
Think of it as a "parallel universe" for your code.
•Branches let work on different parts of a project, like new features 
or bug fixes, without interfering with the main branch.



Common Reasons to Create a Branch

•Developing a new feature
•Fixing a bug
•Experimenting with ideas



Essential Git Branching Commands

•List branches: git branch
•Shows all local branches; the current one is marked with an asterisk (*).



•Create a branch: git branch <name>
•Creates a new branch but keeps you on your current one.



•Switch branches: git switch <name> (or git checkout <name>)
•Moves your working directory to the specified branch.



•Create and switch:git switch -c <name> (or git checkout -b <name>)
•A shortcut to create a new branch and immediately switch to it.



•Merge a branch: git merge <name>
•Combines changes from <name> into your current branch.



•Delete a branch: git branch -d <name>
•Safely deletes a branch after it has been merged. Use -D to force delete unmerged work.



•Rename a branch: git branch -m <old-name> <new-name>
•Renames your local branch. 






git branch 

•git switch is a modern, focused command introduced in Git 
version 2.23 specifically for switching branches,
•git checkout is an older, multi-purpose command that can both 
switch branches and perform other actions like restoring files. 



Creating & Switching Branches

•git branch <branch-name>: Creates a new branch at the current 
commit.
•git checkout -b <branch-name>: Creates a new branch and 
immediately switches to it.
•git switch -c <branch-name>: A modern alternative to checkout -b 
for creating and switching.
•git branch -c <old-name> <new-name>: Copies an existing branch 
to a new name. 



Merging Branches

•git merge <branch-name>: Merges the specified branch into your 
currently checked-out branch.
•git merge --no-ff <branch-name>: Forces a merge commit even if a 
"fast-forward" is possible, preserving history.
•git merge --squash <branch-name>: Combines all changes from 
the branch into a single commit on the current branch.
•git merge --abort: Cancels a merge in progress if conflicts occur. 



Deleting Branches

•git branch -d <branch-name>: Deletes a local branch safely (only if it 
has been merged).
•git branch -D <branch-name>: Force deletes a local branch, even if it 
has unmerged changes.
•git push <remote> --delete <branch-name>: Deletes a branch from a 
remote repository (e.g., GitHub).
•git branch --merged | grep -v "\*" | xargs-n 1 git branch -d: Deletes all 
local branches that have already been merged into your current 
branch.
•git fetch --prune: Cleans up local references to remote branches that 
have already been deleted on the server. 



Listing & Managing

•git branch: Lists all local branches.
•git branch -a: Lists all branches, both local and remote.
•git branch -m <old-name> <new-name>: Renames a branch.
•git branch --merged: Lists branches that have been merged into 
the current one. 



Core Workflow Example

•To work on a new feature safely, follow these standard steps:
•Start from main: git switch main followed by git pull to ensure you 
have the latest code.
•Create feature branch: git switch -c feature-login.
•Work and commit: Make changes, then run git add . and git 
commit -m "Add login logic".
•Merge back: Switch to main (git switch main) and merge: git merge 
feature-login.
•Clean up: Delete the feature branch: git branch -d feature-login. 



Merging Branches

•Merging combines changes from one branch into your current branch. 
•Switch to the target branch





 git checkout main or 

 git switch main

•Merge the feature branch into the current (main) branch:




 git merge feature/new-design

•



Deleting Branches

•Once a feature is merged, the branch can be deleted locally and remotely. You cannot delete the branch you are currently 
on. 
•Delete a local branch (safe mode):





git branch -d feature/new-design

This command only deletes the branch if it has been fully merged into the current branch.

•Force delete a local branch:




 git branch -D feature/new-design

 Use the uppercase -D flag to force deletion of an unmerged branch, which means any unique changes on that branch will be lost if not merged elsewhere.

•Delete a remote branch:




 
git push origin --delete feature/new-design

 or the shorter version:

 git push origin :feature/new-design 


 Replace origin with the name of your remote if it's different.

Collaboration in git

•Collaboration in Git is a distributed version control process that 
allows multiple developers to work on the same project 
simultaneously without overwriting each other's changes. 
•It uses features like branching, merging, and pull requests on 
hosting platforms (e.g., GitHub, GitLab) to manage code 
integration and review. 



Core Concepts

•Distributed System: Every developer has a complete local copy of the 
project's history, allowing them to work asynchronously and 
independently of a central server until they need to sync changes.
•Branching: Developers create isolated "branches" to work on new 
features or bug fixes. This keeps the main codebase (usually the main 
or master branch) stable while experimental work is in progress.
•Remote Repositories: A shared repository hosted online (like on GitHub 
or GitLab) serves as the central point for all collaborators to exchange 
changes.
• Pull Requests (or Merge Requests): A formal mechanism used to 
propose changes and initiate a discussion/code review before 
integrating code into the main branch, ensuring code quality. Common 
Workflow



Common Workflow

•A typical Git collaboration workflow involves the following steps: 
•Sync Local with Remote: Start by updating your local repository with the latest 
changes from the shared remote repository using git pull or git fetch and git 
merge.
•Create a Branch: Create a new local branch for your specific task: git checkout -
b [branch-name].
•Develop and Commit: Make your changes locally, staging them with git add and 
committing them with git commit -m "descriptive message".
•Push Changes: Upload your local branch and commits to the remote repository: 
git push origin [branch-name].
•Create a Pull Request: On the hosting platform's web interface, open a pull 
request to merge your changes into the main branch. This allows teammates to 
review your code and provide feedback.
•Review and Merge: After code review and approval, a supervisor or team 
member merges the pull request into the main branch.
•Resolve Conflicts: If two developers modify the same lines of code, Git will flag a 
merge conflict, which must be resolved manually before the merge can be 
completed. 






Benefits

•Prevents Overwriting: Git automatically flags conflicting changes, 
preventing work from being accidentally lost.
•Code Quality: The pull request and code review process helps 
teams maintain high code quality by catching errors and 
suggesting improvements.
•Knowledge Sharing: Team members learn from each other's code 
and problem-solving approaches during collaboration and review.
•Faster Development: Different team members can work on 
separate parts of the project simultaneously, accelerating the 
development process. 



•User1 (repo owner) and User2 (collaborator) using GitHub, involving setting up a shared repository, 
cloning, branching, committing, pushing, and pulling changes.
•Initial Setup (User1)


 
•Create Repository: User1 creates a new repository on GitHub (e.g., project-repo).
•Add Collaborator: User1 navigates to Settings > Collaborators > Add people and invites User2.
•Local Clone: User1 clones the repository: git clone <URL>.
•Initial Commit: User1 creates a file, commits it, and pushes:


git add file.txt

git commit -m "Initial commit"

git push origin main


Collaborative Workflow (User1 & User2)

•User2 accepts the invitation, then both follow this workflow: 
1.Clone the Repo (User2): User2 clones the repository: git clone <URL>.
2.Create a Branch (User2): User2 creates a new branch for their work:





git checkout -b feature/user2-updates

•Work and Commit (User2): User2 modifies file.txt, commits, and pushes to 
the branch:


git add file.txt

git commit -m "User2 updates file"

git push origin feature/user2-updates

•Pull Request (User2): User2 creates a Pull Request (PR) on GitHub to merge 
feature/user2-updates into main.
•Review and Merge (User1): User1 reviews the PR and clicks "Merge pull 
request" on GitHub.
•Update Local Repo (User1 & User2): Both users pull the changes to update 
their local main branches:


git checkout main

git pull origin main


Key Commands Used

•git clone <url>: Copy a repository.
•git checkout -b <branch>: Create and switch to a new branch.
•git add . / git commit -m "...": Save changes locally.
•git push origin <branch>: Share changes.
•git pull origin main: Update local repository.
