To create a JAX-WS client using a QName, you typically use the javax.xml.ws.Service class to programmatically discover the service and its port. This is known as a Dynamic Proxy Client. 
Basic JAX-WS Client Example with QName

This example demonstrates how to connect to a web service by specifying its WSDL location and the specific service name using a QName. 
java

import java.net.URL;
import javax.xml.namespace.QName;
import javax.xml.ws.Service;
import com.example.HelloWorld; // Your Service Endpoint Interface (SEI)

public class JaxWsClient {
    public static void main(String[] args) throws Exception {
        // 1. Define the WSDL URL
        URL url = new URL("http://localhost:8080/ws/hello?wsdl");

        // 2. Create the QName for the Service
        // 1st param: Target Namespace from WSDL
        // 2nd param: Service Name from WSDL
        QName qname = new QName("http://example.com", "HelloWorldImplService");

        // 3. Create the Service factory
        Service service = Service.create(url, qname);

        // 4. Extract the Port (the actual interface proxy)
        HelloWorld hello = service.getPort(HelloWorld.class);

        // 5. Invoke methods
        System.out.println(hello.getHelloWorldAsString("User"));
    }
}
Key Components Explained

QName: The javax.xml.namespace.QName represents a "Qualified Name" in XML. It identifies the service by combining a namespace URI and a local part (the service name). You can find these values in the <wsdl:definitions> and <wsdl:service> tags of your WSDL document.

Service.create(): This factory method parses the WSDL and prepares the client to communicate with the specific service identified by the QName.
service.getPort(): This returns a proxy object that implements your Service Endpoint Interface (SEI). Calling a method on this object triggers a SOAP request to the server. 

Advanced: Creating a Client with Port QName 

If a service has multiple ports (e.g., one for SOAP 1.1 and one for SOAP 1.2), you can specify the port explicitly using its own QName as shown in IBM's JAX-WS documentation: 
java

QName portName = new QName("http://example.com", "HelloWorldPort");
HelloWorld hello = service.getPort(portName, HelloWorld.class);

wsimport: If you don't have the Java interface (SEI) yet, use the wsimport tool bundled with the JDK to generate the necessary client-side artifacts from a WSDL.
Dispatch API: For developers who need to work directly with XML payloads rather than Java objects, the service.createDispatch() method allows for dynamic XML messaging.

To create a JAX-WS client using QName, you typically follow a "Dynamic Proxy" approach. This allows you to connect to a web service at runtime without relying solely on static stubs generated by tools like wsimport. 
1. Understanding QName Components
A QName (Qualified Name) in JAX-WS represents the specific service or port defined in the WSDL. It consists of two parts:
Namespace URI: The targetNamespace found in the root <wsdl:definitions> element.
Local Part: The name attribute of the <wsdl:service> or <wsdl:port> element. 
2. Implementation Example
This example demonstrates how to create a client for a hypothetical "HelloWorld" service.
java
import java.net.URL;
import javax.xml.namespace.QName;
import javax.xml.ws.Service;
// Import your Service Endpoint Interface (SEI)
import com.example.ws.HelloWorld; 

public class JaxWsClientExample {
    public static void main(String[] args) {
        try {
            // 1. Define the WSDL URL
            URL wsdlLocation = new URL("http://localhost:8888/ws/hello?wsdl");

            // 2. Define the QName for the Service
            // Param 1: Namespace URI from WSDL
            // Param 2: Service Name from <wsdl:service name="...">
            QName serviceName = new QName("http://example.com", "HelloWorldImplService");

            // 3. Create the Service instance
            Service service = Service.create(wsdlLocation, serviceName);

            // 4. Extract the Port (Proxy)
            // You can also use a QName for the port if there are multiple ports
            HelloWorld helloPort = service.getPort(HelloWorld.class);

            // 5. Invoke the Web Service method
            String response = helloPort.getGreeting("World");
            System.out.println("Server Response: " + response);

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
3. Key Methods and Variations
Service.create(URL, QName): This is the standard way to initialize the service factory. As noted in the Oracle WebLogic documentation, passing the WSDL URL allows the client to validate the service contract at runtime.
service.getPort(QName, Class): If your WSDL defines multiple ports (e.g., one for SOAP 1.1 and one for SOAP 1.2), you should use a QName for the specific port to ensure you connect to the correct endpoint.
Dynamic Dispatch: If you do not have the Java Interface (SEI) class available, you can use the Dispatch API which works with SOAPMessage or XML payloads directly. 
4. Common Troubleshooting
Wrong Namespace: Ensure the URI in new QName(...) exactly matches the targetNamespace in your WSDL. A missing trailing slash or a typo will result in a WebServiceException.
Service Name Mismatch: The local part must match the name attribute in the <service> tag at the very bottom of the WSDL file.
JDK Versions: For Java 11 and later, JAX-WS is no longer part of the standard JDK. You must include the Jakarta XML Web Services dependencies in your pom.xml or build file.

JAX-WS clients can be created using javax.xml.namespace.QName and javax.xml.ws.Service to dynamically lookup WSDL information without generating client stubs. This requires defining the target namespace and service name, followed by obtaining the port from the service, a direct alternative to wsimport. 

JAX-WS QName Client Example
java
import java.net.URL;
import javax.xml.namespace.QName;
import javax.xml.ws.Service;
// Import your Generated Service Endpoint Interface (SEI)
import com.example.HelloWorld;

public class Client {
    public static void main(String[] args) throws Exception {
        // 1. WSDL URL
        URL url = new URL("http://localhost:9999/ws/hello?wsdl");

        // 2. QName: Namespace + Service Name (found in WSDL)
        QName qname = new QName("http://ws.example.com/", "HelloWorldImplService");

        // 3. Create Service
        Service service = Service.create(url, qname);

        // 4. Get Port/Proxy
        HelloWorld hello = service.getPort(HelloWorld.class);

        // 5. Call methods
        System.out.println(hello.getHelloWorldAsString("User"));
    }
}

why wsimport use why not qname

The choice between using wsimport and the QName/Service API involves a trade-off between development simplicity and runtime flexibility. These are not mutually exclusive, but rather represent two different styles of web service client development.

Static Proxy Approach (wsimport):

Abstraction: The wsimport tool generates strongly-typed Java stubs (proxies) from a WSDL.

Simplicity: Developers can invoke web service methods as if they were local Java methods, without needing to know the granular XML details or SOAP headers.

Automation: It handles complex XML-to-Java mappings using JAXB internally, which eliminates the need to manually construct XML payloads. 

Dynamic / Manual Approach (QName & Service API):

Granular Control: Using the QName class and Service API allows for "finer controls" over client-service communication.

Runtime Flexibility: This approach is necessary when the WSDL location or service details are only known at runtime, or when you need to dynamically change the URL.
Lower-level Access: It is often used with the JAX-WS Dispatch API to work directly at the XML message level rather than with generated Java objects.
