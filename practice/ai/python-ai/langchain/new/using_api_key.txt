## --- Response ---
Below is a **minimal, ready-to-run** example that shows how to switch from the default *local* Ollama endpoint to the **hosted Ollama service** (the one that requires an API key).  
All you have to do is tell `OllamaLLM` (or `ChatOllama` for chat-style models) two extra arguments:

| Argument | What it does |
|----------|--------------|
| `base_url` | URL of the hosted Ollama API (normally `https://api.ollama.com/v1`). |
| `api_key`  | Your personal Ollama API key (you can also read it from an environment variable). |

> **Tip:** Keep the key out of source control - put it in an environment variable (`OLLAMA_API_KEY`) or a `.env` file and read it with `os.getenv()`.

---

## 1. Install the right package version

```bash
# Make sure you have the latest LangChain-Ollama integration
pip install -U "langchain-ollama>=0.2.0"
```

> The `langchain-ollama` package ships the `OllamaLLM` class that knows how to talk to the hosted API as of v0.2.0. Earlier releases only supported the local HTTP server.

---

## 2. Full script (single-turn "prompt -> LLM")

```python
# ------------------------------------------------------------
#   langchain4_remote.py
# ------------------------------------------------------------
import os
from langchain_ollama import OllamaLLM          # or ChatOllama for chat models
from langchain_core.prompts import PromptTemplate

# ------------------------------------------------------------------
# 1.  Pull the API key from the environment (recommended)
# ------------------------------------------------------------------
OLLAMA_API_KEY = os.getenv("OLLAMA_API_KEY")
if not OLLAMA_API_KEY:
    raise RuntimeError(
        "❌ OLLAMA_API_KEY not set. "
        "Export it in your shell or put it in a .env file."
    )

# ------------------------------------------------------------------
# 2.  Create the LLM client that points at the hosted service
# ------------------------------------------------------------------
llm = OllamaLLM(
    model="qwen3.5:2b",          # any model that Ollama hosts (e.g. "llama3.2:1b")
    temperature=0.1,
    # 👉 Tell LangChain to use the remote endpoint + your key
    base_url="https://api.ollama.com/v1",   # <-- hosted Ollama API
    api_key=OLLAMA_API_KEY,
    # optional: increase timeout if you expect long generations
    request_timeout=120,
)

# ------------------------------------------------------------------
# 3.  Prompt template (same as your original code)
# ------------------------------------------------------------------
prompt = PromptTemplate(
    input_variables=["topic"],
    template="Tell me about {topic}",
)

# ------------------------------------------------------------------
# 4.  Build the chain: Prompt -> LLM
# ------------------------------------------------------------------
chain = prompt | llm

# ------------------------------------------------------------------
# 5.  Invoke the chain
# ------------------------------------------------------------------
response = chain.invoke({"topic": "java"})   # try any topic you like
print("\n=== Ollama response ===")
print(response)
```

### How it works
1. **Environment variable** - `OLLAMA_API_KEY` is read once at start-up.  
2. `OllamaLLM(..., base_url=..., api_key=...)` tells the client to hit `https://api.ollama.com/v1` instead of the default `http://localhost:11434`.  
3. The rest of the code (`PromptTemplate`, the `|` pipe operator, `chain.invoke`) stays exactly the same as in your local-only script.

## 3. Using a **chat-style** model (e.g. `qwen3.5:2b` supports chat)

If you want the richer chat-completion API (messages with roles), just swap `OllamaLLM` for `ChatOllama`:

```python
from langchain_ollama import ChatOllama

chat_llm = ChatOllama(
    model="qwen3.5:2b",
    temperature=0.1,
    base_url="https://api.ollama.com/v1",
    api_key=OLLAMA_API_KEY,
)

# Example with a system + user message
messages = [
    ("system", "You are a concise, friendly tutor."),
    ("user",   "Explain the difference between a list and a tuple in Python."),
]

print(chat_llm.invoke(messages))
```

`ChatOllama` returns a `ChatMessage` object that `print`-s nicely, or you can access `message.content`.
