error_reporting not works in php

It’s a classic PHP headache. You think you’ve told the server to speak up, but it stays stubbornly silent. Usually, this happens because there are two "bosses" in this scenario: the global configuration (php.ini) and your local script commands.

Here is a checklist to get those errors showing up so you can actually fix your code.

1. The "Force Everything" Snippet
Place this at the absolute top of your PHP file. If this works, it means your global settings are set to hide errors.

PHP
<?php
error_reporting(E_ALL);
ini_set('display_errors', 1);
ini_set('display_startup_errors', 1);
2. Check for Syntax Errors
If your script has a Parse Error (like a missing semicolon or bracket), the script won't even run. Since the script never executes, your ini_set commands inside that script never fire.

The Fix: Check your server’s global error_log file (often found in /var/log/apache2/error.log or /var/log/nginx/error.log).

3. The php.ini Heavy Lifter
If you have access to your server configuration, the most reliable method is editing the php.ini file directly. This ensures errors are caught before the script even starts.

Locate your php.ini (run phpinfo(); to find the path).

Search for these lines and set them:

display_errors = On

error_reporting = E_ALL

Restart your web server (Apache/Nginx/PHP-FPM) for changes to take effect.

4. Common "Gotchas"
The @ Operator: Check if your code has an @ symbol before a function call (e.g., @include(...)). This "shut up" operator tells PHP to ignore errors for that specific line.

Production Environment: If you are using a framework like Laravel or Symfony, they often have their own error handling logic in .env files (e.g., APP_DEBUG=true).

Host Restrictions: Some shared hosting providers force display_errors to Off for security and won't let you override it via script. In that case, you must rely on the log files.

How PHP Processes Errors
Quick Tip: If you're on a browser and see a "500 Internal Server Error" but a blank screen, it’s almost certainly a syntax error that crashed the engine before your error_reporting(E_ALL) could even load. Check those logs!
