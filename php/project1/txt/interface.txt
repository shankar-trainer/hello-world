In PHP, an interface is a blueprint that defines which public methods a class must implement, 
without providing the actual code for those methods. 
It acts as a "contract" that ensures any class following it will have a specific set of behaviors.

Key Features
    Method Signatures Only: Interfaces declare the names and parameters of methods but cannot contain any "body" (logic).
    Public Access: All methods in an interface must be declared as public.
    Multiple Implementation: Unlike classes, where you can only inherit from one parent, a single class can implement multiple interfaces.
    
    Constants: Interfaces can contain constants, which cannot be overridden by implementing classes.
    Properties (New): As of PHP 8.4, interfaces can also declare properties, provided they specify if the property is readable, writeable, or both.

Basic Syntax
You define an interface using the interface keyword and implement it using the implements keyword.
php

interface Logger {
    public function log(string $message);
}

class FileLogger implements Logger {
    public function log(string $message) {
        echo "Logging to file: $message";
    }
}

Use code with caution.
Why Use Interfaces?

Polymorphism: They allow you to use different classes interchangeably as long as they implement the same interface.
Standardization: Useful in large projects to ensure different developers' classes interact correctly.
Flexibility: You can change a class's internal logic without breaking the code that calls its methods, provided the interface remains the same.

===================
To "inherit" from multiple sources using interfaces, list them after the implements keyword:

interface Logger {
    public function log(string $message);
}

interface Encryptor {
    public function encrypt(string $data);
}

// Class simulating multiple inheritance
class SecureLogger implements Logger, Encryptor {
    public function log(string $message) {
        echo "Logging: " . $message;
    }

    public function encrypt(string $data) {
        return base64_encode($data);
    }
}

php interface vs abstract class

In PHP, interfaces and abstract classes both define contracts for other classes to follow, but they serve different architectural purposes. [1, 2]  
Quick Comparison Table 

 Interface | Abstract Class  |

| Implementation | Pure template; no method bodies allowed. | Can have both abstract (empty) and concrete (implemented) methods.  |
| Properties | Cannot have properties/variables. | Can have properties just like a normal class.  |
| Inheritance | A class can implement multiple interfaces. | A class can inherit from only one abstract class.  |

When to Use Which? 
Use an Interface when: 
• Unrelated classes need to share a common behavior (e.g., both a  and a  might be ). 
• You want to define a strict public contract for what an object can do, regardless of how it's built. 
• You need to bypass PHP's single-inheritance limit by having a class fulfill multiple roles. [1, 5, 10, 13, 14, 15]  

Use an Abstract Class when: 
• You want to provide a base skeleton with shared code that child classes can reuse (e.g., a  or  parent). 
• You need to store state (properties) in the parent class. 
• Your classes are closely related and share a significant amount of identical logic. [2, 7, 15, 16, 17]
