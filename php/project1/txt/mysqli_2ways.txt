MySQLi (MySQL Improved) in PHP can be used in two ways: the Object-Oriented (OO) way and the Procedural (normal) way. 
Both methods provide similar functionality, 
including support for prepared statements to prevent SQL injection, but they differ in syntax. [1, 2, 3, 4, 5]

1. Object-Oriented (OO) Way
The object-oriented way involves creating instances of the mysqli class and calling methods on those objects. This approach is generally preferred for cleaner, more organized code, especially in modern MVC applications. [1, 2, 3]
Example:
php
// 1. Connect
$mysqli = new mysqli("localhost", "user", "password", "database");

// Check connection
if ($mysqli->connect_error) {
    die("Connection failed: " . $mysqli->connect_error);
}

// 2. Query
$result = $mysqli->query("SELECT id, name FROM users");

// 3. Fetch Data
while ($row = $result->fetch_assoc()) {
    echo $row['name'] . "<br>";
}

// 4. Close
$mysqli->close();
Use code with caution.

2. Procedural (Normal) Way
The procedural approach uses functions, where the connection object is typically passed as the first parameter to the function. This is often preferred by developers transitioning from the old mysql extension. [1, 2, 3, 4]
Example:
php
// 1. Connect
$conn = mysqli_connect("localhost", "user", "password", "database");

// Check connection
if (!$conn) {
    die("Connection failed: " . mysqli_connect_error());
}

// 2. Query
$result = mysqli_query($conn, "SELECT id, name FROM users");

// 3. Fetch Data
while ($row = mysqli_fetch_assoc($result)) {
    echo $row['name'] . "<br>";
}

// 4. Close
mysqli_close($conn);
Use code with caution.
Key Differences at a Glance
Feature [1, 2, 3, 4, 5]
Object-Oriented	Procedural
Connection	$mysqli = new mysqli(...)	$conn = mysqli_connect(...)
Querying	$mysqli->query(...)	mysqli_query($conn, ...)
Error Handling	$mysqli->connect_error	mysqli_connect_error()
Fetch Row	$result->fetch_assoc()	mysqli_fetch_assoc($result)
Style	Concise, cleaner, reusable	Similar to old mysql extension
Which to use?
•	Object-Oriented is generally recommended for new projects because it is more maintainable.
•	Procedural is fine for small scripts or when migrating legacy code. [1, 2, 3]
